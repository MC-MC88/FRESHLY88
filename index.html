How this works. We query the GitHub Search API for repositories created inside the selected time window. Two parallel requests go out: one sorted by stars (so genuinely popular projects are not buried) and one sorted by updated, which for a repo a few hours old is basically the same as its creation time. Results are merged and de-duplicated.
Why "fair". The default order is a full shuffle. Every repo has the same probability of landing at the top, regardless of who wrote it or how many stars it collected.
Rate limits. GitHub gives anonymous visitors 10 search requests per minute. Dropping in a personal access token raises that to 30. The token stays in this browser's localStorage and is sent only to api.github.com.

GitHub API token Optional. Raises your request limit.

GitHub limits how often an anonymous visitor can hit its search API. Without a token you get about 10 requests per minute. Freshly88 spends two requests per load — one for the most-starred repos, one for the newest — which means you can browse roughly four pages before you have to wait for the window to reset.

Creating one

  1. Open the GitHub token page while signed in.
  2. Give it any name — Freshly88 is fine.
  3. Leave every scope checkbox unchecked. Public data is all we read, so the token needs zero permissions.
  4. Set an expiry you are comfortable with. 90 days is a reasonable default.
  5. Click Generate token and copy the string starting with ghp_ or github_pat_.

Storage and safety

The token is kept in your browser's localStorage and attached only to requests going to api.github.com. There is no backend here — no server sees it, and nothing is logged. Because it carries no scopes it can only read public information, so the worst case if it ever leaked is someone borrowing your rate limit. Still, use the Remove button when you are done with a shared machine.
